## 0. 结论先行

1. **单日链的成本结构是三分量**：`full-fit`（决策日一次全训练行后验）+ `prequential`（对每个历史决策行一次因果 fit）+ `决策`（innovation/kelly/诊断）。三者中 `prequential` 的行数随决策日单调增长：`n ≈ t − WARMUP − 1`（WARMUP=256）。
2. **两个必须分开的场景**：
   - **早期窗口（D-089 阶梯，t≈257–340）**：`prequential` 20–80 行；已知卡点为逐行 fit 的求积固定成本（67 行串行 ≈200s/日【转引】），已落盘行级并行 + 增量维护但**单日链加速后实测尚未发生**。这是 60-day 段 6 的直接目标。
   - **晚期真实窗口（F6，t≈14291–14310）**：`prequential` 行数 ≈1.4 万行。即使按最乐观的单点成本 2.5ms 估算，仅每行「441 粗扫描点」就 ≈1.1s×1.4e4 ≈ 4.3 小时，**结构性超出一切单命令预算**。因此 F6 单日链 ≤55s 在现行数学语义下不可达；这不是实现缺陷，是 P0-1「严格因果残差历史」的数学后果，须走 owner 裁决（分批/长跑/验证范围重定义）。
3. **可立即见效且零数学风险的是配置项**：BLAS 线程 1（单点 8.36ms → 2.52ms，≈3×）为批次 8 实测【转引】；属运行时数值工程配置裁决（owner 域），不是本文的实现面。
4. **对 60-day/早期窗口最有杠杆的数学加速候选依次是**：(c) 跨行 warm start（外推 3–5×，PREQUENTIAL-COST-1 已给契约草案）；(a) 高阶局部求积规则（3 点主 + 4 点对照，每 cell 25 点，收敛指数上移，cells 数下降）；(d) 粗扫描缩减/复用；(b) 坐标变换/预条件登记为 Gate-1 后续，(e) 并行/内存属 CS 层。
5. **本文不宣布任何性能达标**：所有收益均为外推，须按第 6 节实验由 DevOps 实测后定稿。

## 1. 单日链成本解剖（事实）

### 1.1 链条（`src/gate0/driver.jl:243-648`，`single_day_decision`）

每个决策日 `t` 的执行顺序（行号为静态阅读时点）：

1. 因果截断、active 域、signal/return、mode 坐标（步骤 0–3，快）；
2. **步骤 7：full posterior**（`:377-378`）——`fit_full_posterior(X_tr, Y_tr; tol=1e-6, max_cells=2048)`，`X_tr = mp.X[rows,:]`，`rows = WARMUP:(t-1)` 中有观察行；
3. **步骤 8：prequential 残差历史**（`:387-390`）——`prequential_residual_rows(X_tr, Y_tr, E_active)`，内部 `for s in 1:n` 对每行 `fit_full_posterior(X[1:s-1,:], Y[1:s-1,:])`（`src/gate0/oof.jl:386-422`）；
4. 步骤 8b–12：二次 resolve、innovation、决策行 feature、adaptive kelly（`:404-521`）。

关键数量关系【事实】：`n = length(rows) ≈ t − WARMUP − 1`（WARMUP=256，`src/geometry.jl`）。

- t=327 → n≈67–70 行（与 PREQUENTIAL-COST-1 的「67 行」一致）；
- t=14305 → n≈14049 行（真数据首日，未见任何证据曾跑到该步骤）。

### 1.2 单次 fit 的求积结构（`src/gate0/posterior.jl`）

- **粗扫描**：`grid = range(-12, 12; length=21)`，441 个点逐点 `logf`（`:761-768`），产出初始域中心 `(m0, mp)` 与峰值参考 `mval`（D-038 bracket 语义，不定义 posterior）。
- **2D 自适应求积**（`adaptive_quadrature_2d`，`:372-537`）：
  - 初始网格 4×4=16 cells；细分 = 最大误差 cell 沿长边二分；预算耗尽 fail loudly（D-067 文本）；
  - **每 cell 求值点数 = 13**：2 点/维 G-L 主规则 4 点（`cell_val`）+ 3 点/维对照 9 点（`cell_err`），外加 `cell_peak` 同 13 点集合的 m 覆盖性维护（vcache 精确坐标缓存，`:406-478`）；
  - 归一化基准 `m` 由 `cell_peak`（13 节点 max）维护，细分后增量更新（`:509-527`，2026-10-10「m 基准修复」）。
- **最终节点**：K=cells 个节点各一次 `_fit_node`；`rank1=true`（DC 形态）时走 SM lazy 路径（O(P²N)，不物化 P×P 的 V），否则物化 O(P³)。

单次 full-fit 的总求值量 ≈ `441 + 13×cells + K`（K≈cells）次 `logf`/`_fit_node` 级动作。

### 1.4 结构性事实：prequential 行数 = 全历史行数

- `prequential_residual_rows` 对 `X` 的**每一行**做一次因果 fit（`oof.jl:386`），这是 P0-1「历史当时真正发生的 forecast surprise」的数学要求，不是可裁剪的实现选择。
- 决策日 t 越大，行数越多；**晚期窗口（F6，t≈1.4e4）的 prequential 是 1.4e4 次 fit**。
- 成本下界（保守）：每行 fit ≥ 441 个粗扫描点；按 BLAS=1 单点 2.5ms（P=911）计，仅粗扫描 ≈1.1s/行 → 1.4e4 行 ≈ 4.3 小时。自适应 cells 与 `_fit_node` 还会倍增。【外推，量级判断】
- 结论：**F6 晚期窗口的「单命令 1 日 ≤55s」在现行数学下不可达**；这不是本次优化能闭合的量级，需要 owner 裁决（第 7 节 U1）。

## 3. 候选优化对比与推荐

### 3.1 (a) 更高阶局部求积规则（推荐，需 E1/E2 定稿）

- **内容**：把 `cell_val`/`cell_err`/`cell_peak` 的节点集升级（如 3 点/维主规则 9 点 + 4 点/维对照 16 点 = 25 点/cell；或 4 点主 16 点 + 5 点对照 25 点 = 41 点/cell）。张量积构造；vcache、细分、tail 证书、预算、fail-loud 全部原样。
- **数学对象**：**不变**（数值积分规则的离散化升级；节点/权重随规则变化属 D-066 numerics 配置）。数值值变化 → 既有断言可能需重基线（预期效应，须逐条归因，不得放宽断言）。
- **收敛阶（推导口径）**：2D 张量 G-L，每维 k 点、全局相对误差 ≈ O(N^{-k})（光滑被积函数；当前 k=2 实测指数 2.014 与之一致）。k=3 → O(N^{-3})；k=4 → O(N^{-4})。
- **净收益估算**：达到同 tol 所需 cells ≈ N₂^{2/k}（由 N₂⁻²=ε 外推）。若 N₂≈2000：k=3 → ≈160 cells、每 cell 25 点 ≈ 4000 点；k=4 → ≈45 cells、41 点 ≈ 1850 点。相对现状 2000×13≈26000 点，理论点数降 5–14×【外推，须 E1 定稿；常数因子未标定】。
- **风险**：
  1. 光滑度与尖峰：log 坐标下被积函数光滑（T327 文档 §1.2 论证），但真数据 logf 量级 -3.68e6、一阶差分大（`gate0_reallimit_firstday_20261010`），高阶差分代理可能不稳定；
  2. 误差代理保守性需重标定（安全因子 s，E2；D-066）；
  3. 每 cell 成本 ×≈1.9（25 vs 13），细分后期更贵。
- **验证**：E1（收敛曲线）+ E2（代理保守性）+ E3（tol 减半稳定性）+ 全量回归重基线。
- **1D 路径是否同步升级**：裁决点（T327 文档 §8-1 已登记；建议首版只动 2D，1D 现状 8192 内绿）。

### 3.2 (b) 坐标变换/预条件（登记，首版不做）

- **方向 1：u₀ 方向解析积分**（DC 形态下 α₀ 只出现在 Λ 首元 + prior）——收益可能大，但属数学加速（Gate-1）独立推导，不在本批。
- **方向 2：线性预条件/仿射变换**——改变积分变量引入 Jacobian；误差代理与 tail 证书的域边界语义需重推；T327 文档已判「域截断/变量变换不解决收敛率问题」。G-L 升级后其边际作用仅是减少 cells，风险中高、收益不明。
- **方向 3：各向异性初始网格**（u₀/u_p 分向分辨率）——数值层，收益中小，可与 (c)/(d) 打包试验。
- **结论**：登记，不首版执行。

### 3.3 (c) 跨行 warm start（推荐，主收益）

- **内容**：prequential 行 s+1 继承行 s 的粗扫描 mode/初始 cell 划分作为起点；证书与 fail-loud 不放松；证书红 → 冷路径回退一次；再失败 → 该行 NaN（行级语义不变）。与 PREQUENTIAL-COST-1 §2-B 同一契约。
- **数学对象**：**不变**（D-038：mode 仅作初始 bracket/域中心；开发守则 §47：warm start 允许，条件是同一数学证书）。
- **收益**：外推 3–5×（PREQUENTIAL-COST-1 §3）；叠加已落盘行级并行（67 行 → 并行后 ≈33s 量级【外推】）后，早期窗口单日链有望进入 55s。
- **风险**：求积路径变化（非逐位等价）——须按「字段级 tolerance + 证书一致 + NaN 行集相同」验收（reference equality 口径待 Manager 裁决，PREQUENTIAL-COST-1 §5-1 已登记）。
- **对晚期窗口**：不改变量级结论（1.4e4 行 × 每行至少粗扫描 ≈ 小时级）；**不得**把 warm start 宣传为 F6 解法。

### 3.4 (d) 粗扫描缩减（推荐，与 (c) 打包）

- **内容**：441 → 81（9×9）或两级扫描（先粗后细）；warm start 生效时可直接复用上行的 mode，跳过全扫描改为局部验证扫描。
- **数学对象**：**不变**（mode/峰值参考仅作初始 bracket；注意 refval 低估方向是 fail-closed 的误报红，不是假绿）。
- **收益**：单行省 ≈0.9s（P=911、BLAS=1）→ 对 67 行 prequential ≈60s（BLAS=1）【外推】；对早期 P 小的场景按比例缩小。
- **风险**：峰值参考低估 → tail 证书误报红（安全方向）；验证以 E5 覆盖。

### 3.5 (e) 其他（CS 层与配置层；登记边界）

- **BLAS 线程配置**：单点 8.36ms（6 线程）→ 2.52ms（1 线程），≈3×；批次 8 明确为「运行时数值工程配置决策（不改 src），需裁决生产在何处设定」。建议裁决：生产与测试 harness 显式 `BLAS.set_num_threads(1)`（与「单线程 slow reference」语义一致），行级并行用 Julia threads。不属本文实现面。
- **行级并行**：已落盘（`oof.jl:386` `Threads.@threads`），与 BLAS 线程嵌套的组合需实测（E4）。
- **内存**：首日 RSS 1703MiB 接近 2048 guard；lazy 路径已避免 P×P 物化；不在数学未定时做内存优化。
- **D-007 层界**：以上 (e) 属 CS 加速/配置层；本设计只登记，不在 Gate-0 数学正确性层内执行。

## 6. 供 DevOps 的验证实验设计

护栏：单命令 ≤60s / RSS ≤2048MiB；existing 配置；串行调度；脚本落受控区（`archive/evidence/...` 或临时目录）；不改 `src/test`；超时如实记录，禁止放宽 tol。
