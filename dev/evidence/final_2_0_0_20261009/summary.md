# KTrader 2.0.0 Final — 发布封版记录

用户要求收紧代码并发布 Final。此次不重写已经验收的数学实现，不新增GPU
后端，不改测试容差、模型参数或依赖版本。

Project.toml 仅将 version = "0.1.0" 改为 "2.0.0"。Final 校验器通过反向
还原这一行并核对原SHA256，证明没有附带的依赖/配置变更。Manifest.toml、
全部已验收 src/test/bin 原文件及必要开发测试库必须逐项匹配原资格快照。
原 acceptance.toml 及历史快照保持不变，不把当时的0.1.0或published=false
改写为新状态。新 RELEASE.toml 描述正式版本，旧凭据只作为可追溯的来源。

本轮收紧的是发布边界：

- 根README替换为正式使用入口，逐轮历史保存为本目录README.pre-final.md。
- 忽略本地数据、诊断、拟合快照和生成的二进制，不删除用户文件。
- CPU源码归档由固定allowlist从v2.0.0标签读取，不从变化中的工作树复制。
  完整测试、必要参考库和验收凭据随包；行情、模型快照、GPU原型和历史长文不随包。
- 新增完整性边界测试、真实包版本/短链路检查和可重复的打包脚本。

封版前原CPU验收独立status已RC0，21项汇总器检查通过（5秒，444MiB）。
这21项是证据核验，不是新增数学回归。Final发布工具边界16项通过（1秒，
361MiB）。真实包加载显示2.0.0，原默认EB/F3/S64小样本流水线13项通过
（4秒，705MiB）。原41文件/22分组覆盖通过源码字节一致性关联，未声称
本轮再次运行整个套件或单进程全套。

无配置远端，因此发布操作为本地Git提交、annotated v2.0.0标签、源码tar.gz
与SHA256文件。不会创建公开仓库、推送数据、发布注册表或调用交易账户。
打包后在独立解包目录运行Final源码校验及release smoke；具体提交、归档哈希
和构建结果由dist/中的发布构建记录给出，不预填或倒改历史日志。

生成工具通过语法检查；一次新增脚本中的行分隔书写错误在执行前修正，未
影响任何CPU实现或验收结果。之前工具拦截了一条合并的只读文件规模探查，
不把它视为已取得的体积清单；最终包大小以实际构建输出为准。
